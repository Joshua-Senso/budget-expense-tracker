# auth — Agent Guide

Authentication + households for the expense tracker. **Bun + TypeScript**, built
on **Better Auth**. Deliberately thin: Better Auth owns identity, sessions,
OAuth, the JWKS, and the household (organization) model — we only configure it
and expose its handler.

> **This workspace is intentionally minimal.** If you find yourself adding
> user/session/household tables, querying them directly, or writing auth/business
> logic here — stop. Identity belongs to Better Auth; application logic belongs to
> the API (`services/api`). Nothing else lives in this service.

The repo-wide layout is in `docs/STRUCTURE.md`; the rules here win for anything
under `services/auth/`.

## Better Auth owns this (do NOT reimplement)

- **Identity & sessions:** `users`, `accounts`, `sessions`, `verifications` tables.
- **OAuth** providers (Google, GitHub, Discord at launch) and the sign-in flow.
- **JWT plugin + JWKS** endpoint (`/api/auth/jwks`), keys held in the `jwks`
  table — for cross-service trust.
- **Organization plugin = households:** `organizations`, `members`, `invitations`
  tables, roles (owner/member), and the invite/accept lifecycle. "Household" is
  just the user-facing label for an organization.
- **Its schema and migrations**, via the Better Auth CLI.

> Tables are **plural**: Better Auth is configured with `usePlural: true` in
> `auth.ts`, so every table it owns is plural (`users`, `sessions`,
> `organizations`, …). App tables in `services/api` reference these by id.

## We write this (the entire surface)

```text
src/
  auth.ts      # the Better Auth instance: db (DATABASE_URL), usePlural: true,
               #   socialProviders, plugins [jwt(), organization()], trustedOrigins, secret/baseURL
  server.ts    # entry (:4000): thin Hono shell mounting auth.handler at /api/auth/*
               #   + a /health route. NO business logic.
  schema/      # GENERATED by `better-auth generate` — CLI-owned, never hand-edit
tests/
  auth.test.ts # bun test — config sanity, JWKS shape, org/household rules
.env.example   # BETTER_AUTH_SECRET, DATABASE_URL, OAuth client IDs/secrets, frontend origin
Dockerfile
```

> Current `src/index.ts` is a placeholder hello server. When wiring Better Auth,
> split it into `auth.ts` + `server.ts` and point the `dev` script at `server.ts`.

## Rules

- **Schema is CLI-managed.** Edit config in `auth.ts`, then
  `bunx @better-auth/cli@latest generate` (writes `schema/`) and `… migrate`
  (applies to Postgres). Never hand-edit `schema/`.
- **Plural tables.** `usePlural: true` is set in `auth.ts` — keep it. Flipping it
  later renames every table (a destructive migration).
- **One database, shared with the API** (ARCHITECTURE §6). Two migration owners:
  Better Auth owns its tables, Alembic owns app tables — keep them distinct;
  neither touches the other's tables.
- **Providers are env-driven.** Add a provider in `auth.ts` reading its client
  id/secret from env; enable it only when those vars are present.
- **Households = organization plugin.** Don't model households yourself. App
  tables reference a household by the organization id (`household_id`).
- **Secrets** (`BETTER_AUTH_SECRET`, OAuth client secrets) live in `.env`
  (gitignored) / host env. Never commit them; never expose them to the frontend.

## Integration contract (other workspaces depend on this — don't break it casually)

- The **frontend** signs in via the Better Auth client and obtains a JWT.
- The **API** verifies that JWT against `GET /api/auth/jwks` (checking issuer,
  audience, expiry) and trusts the **`sub` claim as the canonical `user_id`**.
  No shared session logic, no per-request callback to this service.
- `trustedOrigins` must include the frontend origin; CORS for `/api/auth/*` is
  handled here.

Changing token claims, issuer, audience, or the JWKS path is a **breaking change
for the API** — coordinate both sides.

## Commands

```
make auth                              # from repo root — run dev server (:4000)
bun run dev                            # same, from services/auth
bun test                               # tests
bunx @better-auth/cli@latest generate  # regenerate schema/ after config changes
bunx @better-auth/cli@latest migrate   # apply auth tables to Postgres (needs `make up`)
```

Rule of thumb: **Makefile = run the service; bun / Better Auth CLI = auth-specific
tasks.**
